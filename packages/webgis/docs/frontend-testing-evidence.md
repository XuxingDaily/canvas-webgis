## 2. R-tree 空间查询基准

执行命令：

```powershell
npm run bench:spatial
```

使用固定随机种子生成 100,000 个点要素和 100 个固定视口，交错执行 25 轮。索引构建
位于计时区间外，基准开始前先验证 R-tree 与线性扫描的查询结果数量完全一致。

| 查询方式 | 平均耗时 | P50 | P95 |
| --- | ---: | ---: | ---: |
| ArrayFeatureClass 线性扫描 | 185.14 ms | 182.13 ms | 204.79 ms |
| Packed R-tree | 0.778 ms | 0.880 ms | 1.100 ms |

Packed R-tree 在该数据分布和视口大小下平均约快 238 倍，P50 约快 207 倍。该指标
衡量已经完成索引构建后的重复视口查询，不包含首次索引构建成本。

第二次独立运行的平均耗时为 193.61 ms 对 0.795 ms，P50 为 195.92 ms 对 0.884 ms，
平均加速约 243 倍。两轮结果支持在简历中使用更保守且易读的“约 200 ms 降至
0.88 ms，提升 200 倍以上”。

## 3. Chrome Canvas 帧绘制基准

执行命令：

```powershell
npm run bench:render
```

基准使用 Windows Headless Chrome 的 Canvas 2D 软件渲染路径，生成 100,000 个点，
在 1200×800 Canvas 上对 120 个固定视口交错执行 5 轮，共测量 600 帧。每一帧包含
清屏、视口查询、坐标转换和可见点绘制，不包含网络请求、MVT 解码、文字标注和浏览器
合成时间。

连续两次独立运行结果：

| 运行 | 线性平均 | R-tree 平均 | 线性 P95 | R-tree P95 |
| --- | ---: | ---: | ---: | ---: |
| 第 1 次 | 1.33 ms | 0.157 ms | 1.8 ms | 0.3 ms |
| 第 2 次 | 1.37 ms | 0.152 ms | 1.9 ms | 0.3 ms |

平均帧 CPU 耗时稳定降低约 88%，加速约 8.5～9.0 倍；P95 约降低 83%。该结果适合描述
“视口筛选与 Canvas 图层绘制耗时”，不应表述为整页 FPS 或包含网络加载的端到端渲染时间。

## 5. 边界与后续测试

当前指标已经覆盖核心纯计算与 Canvas 绘制路径，但若要证明完整地图应用体验，建议继续补充：

- 使用真实广州 GeoJSON/MVT 数据，而不是均匀随机点；
- 记录 MVT 下载、Protobuf 解码、瓦片缓存命中率和首屏完成时间；
- 测试线、面复杂几何以及文字碰撞检测，而不仅是点要素；
- 在普通 Chrome 可见窗口中使用 Performance API 记录交互长任务与掉帧；
- 在不同硬件上重复运行并报告设备、浏览器版本和至少 5 轮结果。
